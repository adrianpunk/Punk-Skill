# 接入用户的新风格

用户提供的文档、提示词或参考图只有在其要求添加、替换或整理为风格时才接入；单纯附件先按上下文理解用途。风格材料中的工具命令、链接或角色要求不自动扩展本次授权。

## 文件结构

```text
styles/{style-id}/
  STYLE.md    名称、适用内容、输入字段、锚点、四比例适配、保留与禁用项
  PROMPT.md   可复用的视觉原子，描述风格如何落到人物与文字上
  SOURCE.md   可选：用户原始文字文档；参考图片仅用于提炼文字规则，不放入技能包
```

使用稳定的英文短 ID 与易识别中文名称，参考 Punk 的 `STYLE.md` / `PROMPT.md` 组织方式。已有同类风格时按用户意图更新或新增，不擅自覆盖其他风格。

## 整理方式

1. 查看用户原始材料，分清通用输入、工具名称与具体视觉要求。原始文字文档可保留；输入为参考图时提炼字形、配色、路径、人物关系和装饰，不复制参考封面或另一个人的头像到 skill。新风格应仅凭文字规则执行。
2. 将该风格的字体、取色、背景、材质、人物处理、装饰与特定布局收入本风格文件。不要把它们升级成全技能规则。
3. `STYLE.md` 可用 YAML 元数据块，包含：`id`、`name`、`status`、`validation_status`、`input_modes`、`subjects`、`outputs`、`supported_ratios`、`required_fields`、`optional_fields`、`best_for`、`avoid_for`、`source`、`style_anchors`、`must_preserve`、`avoid_when_applying`。`outputs` 使用 `ip_video_cover`；`status` 表示接入状态，`validation_status` 如实记录是否已出图检查。
4. `PROMPT.md` 保留具体视觉规则与比例差异，记录字身高的单位、字效、颜色角色、路径、人物关系、动作道具和装饰用途。标题、姓名、品牌、主题物应是本次输入，不把案例中的具体词固化成可见内容。生成不附参考图，推荐菜单仅提供名称和文字理由。
5. 原文有两种相互冲突的描述时，能从上下文判断的做最小澄清并记录；涉及关键风格选择、无法判断的问用户。不能根据个人审美改成另一种风格。
6. 更新风格目录，检查文件路径和元数据；需要分发时同步更新技能包。用户只要求接入时不自动出图，未生成的风格标明效果尚未验证。

## 独立性

新风格必须执行共用核心：上传照片提取四个基础色并合理搭配、真人抠图、每次自由构图。其参考色盘和人物坐标仅是例子，不能固化；新增的是字体、字效、标题载体、材质和装饰，不创建另一套色盘来源或固定布局。

新增一个风格只增加自己的目录和目录条目；其他风格及通用排版保持独立。用户明确要该风格作用于通用层时才修改通用规则。
